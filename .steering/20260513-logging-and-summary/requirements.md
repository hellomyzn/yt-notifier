# requirements.md

## 概要

通知フローのログ出力強化と、ジョブ実行の最終サマリー出力機能を追加する。
最終的にはそのサマリーを Discord の専用チャンネルへ通知する。

---

## ユーザーストーリー

- 運用担当者として、動画情報の取得だけでなく通知送信時にもログが出力されてほしい。  
  現状は取得ログしかなく、通知が本当に走っているか追いづらい。

- 運用担当者として、ジョブ終了時に「どのチャンネルが何件新着で何件通知されたか」を一目で確認したい。

- 運用担当者として、フェッチにかかった時間・通知にかかった時間・合計時間を知りたい。

- 運用担当者として、最終サマリーを Discord の専用チャンネルに投稿してほしい。  
  ログを直接見なくても結果が確認できるようにしたい。

---

## 受け入れ条件

1. **通知時のログ**
   - `Notify` が呼ばれるたびに `[カテゴリ] チャンネル名 - タイトル` の形式でログ出力される。

2. **最終サマリーログ（標準ログ）**
   - ジョブ終了時に以下が出力される。
     - 合計実行時間 / フェッチフェーズ時間 / 通知フェーズ時間
     - 有効チャンネル総数 / 新着ありチャンネル数 / フェッチエラー数
     - 新着動画総数 / 通知成功数 / 通知失敗数
     - チャンネル別の新着数・通知数（新着ありチャンネルのみ）
   - 既存の `feed stats` / `notification stats` ログはそのまま維持する。

3. **最終サマリーの Discord 通知**
   - `app.yaml` に `summary_webhook_env` キーを追加し、対応する env 変数名を指定できる。
   - `webhooks.env` に `DISCORD_WEBHOOK_SUMMARY=<URL>` を設定すれば Discord へ投稿される。
   - `summary_webhook_env` が未設定 / webhook URL が空の場合は通知をスキップする（エラーにしない）。
   - 投稿内容に含める項目：
     - 実行時間（合計 / フェッチ / 通知）
     - チャンネル件数（新着あり / 総数）
     - 動画件数（新着 / 通知 / 失敗）
     - フィード内訳（RSS / API / フォールバック / 飽和）
     - YouTube API 使用量（リクエスト数・クォータ）—— 使用した場合のみ
     - 通知リトライ件数 —— 発生した場合のみ
     - チャンネル別の通知件数（新着ありチャンネルのみ）

4. **後方互換性**
   - 既存のテストが引き続き通ること。
   - `summary_webhook_env` を設定しなくても従来通り動作すること。

---

## 制約事項

- ライブラリの追加なし（stdlib のみ）。
- Discord embed の `description` フィールド上限（4096 文字）を超えないよう制御する。
- YouTube API メトリクス（`ytRepo.Metrics()`）を `main.go` から `RunOnce` 内に移動し、サマリーに統合する。
