# requirements.md

## 概要

フェッチ処理に関する4つの改善をまとめて実施する。

---

## 改善一覧

### 1. 不要な YouTube API エスカレーション削減

#### 背景・課題
RSS が15件（上限）を返した場合でも、通知済み履歴と照合することで不要な API 呼び出しを削減できる。
RSS の15件の中に通知済み動画が1件以上あれば「前回実行との連続性がある」= 15件ウィンドウの外に新着はないと判断できる。
現状は約526件の API 呼び出しのうち約514件が不要で、クォータを無駄に消費している。

#### 受け入れ条件
- RSS 15件の中に通知済みが1件以上含まれる → API エスカレーションしない
- RSS 15件が全て未通知 → 従来通り API へエスカレーション（初回 or 大量投稿チャンネル）
- `fetch_limit >= 15` チャンネルの挙動は変更しない（引き続き直接 API を使う）
- 新着動画の検出漏れが発生しないこと

---

### 2. フェッチログのチャンネル名表示

#### 背景・課題
現状のログは `channel=UCxxxxxx` のような ID 表示で読みづらい。
チャンネル名に変えることで、どのチャンネルで何が起きているか一目でわかるようにする。

#### 受け入れ条件
- `feed_service.go` 内の全ログで `ch.ChannelID` を `ch.Name` に変更する
- 例: `youtube api fetch failed for channel=UCxxxxxx` → `youtube api fetch failed for channel=テクノロジーch`

---

### 3. フェッチ後の新着動画数ログ出力

#### 背景・課題
現状、フェッチが完了しても何件の新着があったかがログに出ない。

#### 受け入れ条件
- `ListNewVideos` の最後に `[チャンネル名] 新着N件` の形式でログ出力する
- 新着0件のチャンネルはログ出力しない（ノイズを減らす）

---

### 4. フェッチ失敗チャンネルのサマリー警告 + YouTube リンク掲載

#### 背景・課題
フェッチエラーが発生したチャンネルが「削除された可能性」なのか「一時的な障害」なのか判断しづらい。
Discord のサマリーにチャンネルリンクを載せれば、ブラウザですぐ確認できる。

#### 受け入れ条件
- Discord サマリーのフェッチエラー行に以下を含める
  - ⚠ 警告文「削除または非公開になった可能性があります」
  - YouTube チャンネルリンク: `https://www.youtube.com/channel/{channelID}`
- ログにも同様の警告文を追加する（標準ログの `printSummary`）

---

## 制約事項

- ライブラリの追加なし（stdlib のみ）
- 改善 1・2・3 は `feed_service.go` の変更で完結させる
- 改善 4 は `job_controller.go` の `printSummary` / `sendDiscordSummary` を変更する
- 既存テストが全て通ること
