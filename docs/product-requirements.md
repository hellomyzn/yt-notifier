# プロダクト要求定義書

## プロダクトビジョンと目的

100〜数百の YouTube チャンネルを定期巡回し、新着動画をカテゴリ別に Discord へ自動通知する。手動確認の手間をなくし、見たいチャンネルの新着を見逃さない。

## ターゲットユーザーと課題・ニーズ

- **ユーザー**: 多数の YouTube チャンネルを横断して追いたい個人
- **課題**: チャンネル数が多すぎて YouTube の通知機能や手動確認では追いきれない
- **ニーズ**: カテゴリ別の Discord チャンネルに自動で流してほしい

## 主要な機能一覧

- F1: チャンネル一覧の読込（CSV）
- F2: YouTube RSS / Data API による新着動画取得
- F3: 差分検知（既通知 videoId の除外）
- F4: Discord Webhook への通知（Embed 形式）
- F5: 通知済み記録（CSV 追記）
- F6: 失敗時のリトライとサマリログ

## ビジネス要件

- 無料運用（GitHub Actions 無料枠）
- 外部サービスへの依存は YouTube RSS / YouTube Data API / Discord Webhook のみ
- 機密情報（Webhook URL・API キー）はリポジトリに含めない

## ユーザーストーリー

- チャンネルを channels.csv に追加するだけで通知対象に加えられる
- カテゴリを app.yaml で定義するだけで Discord の振り分け先を変えられる
- 同じ動画が重複して通知されない

## 受け入れ条件

- 1 日 2 回の GitHub Actions 実行で新着動画が Discord に届く
- 通知済みの動画は次回以降スキップされる
- 1 回の実行が GitHub Actions の制限時間内に完了する

## 機能要件

- チャンネルごとに fetch_limit を設定できる（15 以上で YouTube Data API を使用）
- カテゴリごとに Discord Webhook の向き先を切り替えられる
- プレミア・ライブ・ショートの通知可否をフィルタ設定で制御できる
- Discord の Rate Limit（429）を受け取ったとき Retry-After を遵守してリトライする

## 非機能要件

- **冪等性**: 同一 videoId の重複通知防止
- **可観測性**: 実行ごとに RSS/API 使用数・通知成功/失敗件数をログ出力
- **セキュリティ**: Webhook URL は Git 未管理ファイルで管理
- **運用コスト**: データベース不使用・CSV のみで完結
